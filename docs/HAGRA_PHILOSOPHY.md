# 하그라 — 제품·디자인 철학

> 상태: 초안 (2026-10-24). 디자인 자산은 아직 전달되지 않았으며, 이 문서는 구현 측이 적용할 원칙과 판단 기준을 정리한다.
> 영문 표기 HAGRA 는 개발 문서용 임시 표기이며 최종 영문 브랜드·로고는 미확정이다.

## 1. 한 문장

**한국의 미감과 생활에 대한 이해를 바탕으로, 누구나 자기 일을 편안하게 해낼 수 있도록 만드는 운영체제.**

## 2. "국산 OS" 를 이렇게 이해한다

하그라는 Linux 커널과 Debian 생태계 위에 만들어진다. 이것을 숨기지 않는다. 국산 OS 라는 말은 "모든 것을 새로 만들었다"
는 뜻이 아니라 다음을 한국에서 책임지고 결정한다는 뜻이다.

| 약속 | 구현 방식 |
|---|---|
| 한국 사용자에게 필요한 입력·글꼴·검색·파일 처리 경험을 기본 품질로 다룬다 | 한글 IME, 한글 글꼴 폴백, 혼합 문자열 정렬·말줄임, 한글 파일명·정렬·검색을 공통 부품과 테스트 대상에 포함한다 (현재 상태는 §6) |
| 한국에서 제품 설계와 사용자 경험을 주도한다 | 디자인 토큰·공통 부품·대표 장면을 저장소에서 관리하고, 디자인 담당과 구현 담당이 같은 장면으로 검증한다 |
| Linux·오픈소스 기반과 자체 개발 영역을 정확하게 공개한다 | `docs/ARCHITECTURE.md` 의 계층표와 각 컴포넌트의 "Debian 패키지 / 자체 구현" 구분을 유지한다 |
| 라이선스를 준수하고 개선 사항을 상위 프로젝트에 기여한다 | 자체 코드는 GPL-3.0-or-later(예정). labwc·wlroots·Qt 에서 발견한 문제는 패치를 상위에 보낸다 |
| 실제 지원 범위와 유지보수 가능성을 명확하게 설명한다 | 지원 하드웨어·검증 환경·미검증 항목을 `DEVELOPMENT_PLAN.md` 에 구분해 기록한다 |

### 2.1 앞선 국산 OS 사례에서 가져오는 교훈

다음은 **관찰**(공개된 사실로 확인 가능한 것)과 **해석**(하그라 팀의 판단)을 나누어 적는다. 모든 국산 OS 를 실패로
단정하지 않는다. 각 항목은 출처와 확인 날짜를 요구하며, 본 세션의 작업 환경은 외부 웹 접근이 제한되어 **아래 사례의
세부 사실은 아직 1차 출처로 재확인하지 못했다.** 재확인 전까지 "확인 필요" 로 표시한다.

| 사례 | 관찰 (확인 필요 — 출처·날짜 기입 전) | 해석 |
|---|---|---|
| 구름 OS (Gooroom) | 공공 부문 보안 데스크톱을 목표로 Debian 기반으로 개발·배포. 공공 조달 중심으로 운영 | 특정 시장(공공)에서 지속 운영된 사례. 범용 확산보다 조달 요건 충족이 설계를 좌우했다 |
| 하모니카 (HamoniKR) | Linux Mint/Ubuntu 기반 한글화 배포판으로 꾸준히 릴리스 | "한글화 품질" 을 핵심 가치로 둔 지속 사례. 독자 UI 보다 기본 품질과 유지보수를 우선했다 |
| TmaxOS / Tmax Gooroom 계열 | 상용 독자 데스크톱 OS 로 발표·시연이 선행되고 범용 확산은 제한적이었다는 평가 | 발표 화면이 실제 사용자 작업보다 앞선 사례로 자주 인용된다. 호환성·성능 약속의 검증이 뒤따르지 않으면 신뢰를 잃는다 |
| 1990년대 K-DOS, 한글 윈도우 계열 시도 | 특정 시기 특정 용도로 쓰이다 중단 | 플랫폼 전환기에 유지보수 역량을 넘어선 범위를 잡으면 중단된다 |

> 재확인 절차: 각 프로젝트의 공식 사이트·저장소·공식 발표를 1차 출처로 삼고, 확인한 날짜와 URL 을 이 표에 추가한다.
> 2차 출처(기사·위키)는 보조로만 쓴다. 확인되지 않은 평가는 해석 열에만 둔다.

### 2.2 하그라가 피할 것 → 저장소에서 어떻게 막는가

| 피할 문제 | 장치 |
|---|---|
| 검증되지 않은 호환성·성능 약속 | 문서의 모든 "지원" 항목은 `tests/` 의 자동 검증 또는 실기기 체크리스트 결과를 가리켜야 한다 (`DEVELOPMENT_PLAN.md` 의 ☑/◐/☐) |
| 발표 화면 우선 개발 | 대표 장면은 실제 세션(labwc + 셸 + 창 장식) 위에서 캡처한다. 목업만으로 "완료" 표시하지 않는다 |
| 유지보수 역량을 넘는 초기 범위 | M1~M6 단계별 범위 고정. 파일 관리자·설정·터미널·설치기는 순서대로, 전 단계 검증 후 착수 |
| 한글 입력·하드웨어 지원 미완성 | 한글 IME 를 M2 에 포함하고 "기본 품질" 항목으로 추적. 실기기 체크리스트에 입력 항목 포함 |
| 설치·업데이트·복구 경험 부족 | M6 설치기, M7 업데이트/복구 경로를 릴리스 조건으로 둔다 |

## 3. 디자인 철학

> 2026-10-24 (H1) 갱신: 한국 전통 문양을 현대적인 운영체제의 **실제 인터페이스**로 재구성한다. 이전의 미니멀리즘 제한은 **폐기**되었다.
> 확정 시안: `design/hagra-dancheong-v1/` (연한 단청, 기본). H2(2026-10-26)에 `design/hagra-dancheong-v2/` (깊은 단청)이 **선택형 테마**로 추가되었다. 같은 조형 강령을 짙은 안료색(목부 녹·녹청·주홍·군청·황토)으로 옮긴 것이며 본문은 분백을 유지한다. 조형 강령은 각 패키지의 `docs/DESIGN_SPEC.md` 가 원본이며 여기서는 요지만 적는다.

### 3.1 조형 강령 (연한 단청)

1. **문양은 중심 표현이다.** 단청의 겹테두리, 연꽃, 구름, 창살, 보자기, 매듭을 적극 사용한다. 배경만 한국적으로 바꾸는 구현은 목표에 미달한다.
2. **역할을 정해 반복한다.** 제목 아래 = 연화 띠, 창틀 모서리 = 결구, 사이드바 하단 = 옅은 창살, 폴더 = 유형별 문양, 하단 패널 = 얇은 띠.
   서로 다른 문양을 모든 표면에 동시에 채우지 않는다.
3. **본문은 장식과 분리해 정확히 읽히게 한다.** 입력 문자열 위, 목록 행 뒤, 클릭 영역 안에는 문양을 두지 않는다. 이것은 미니멀리즘이 아니라 작업용 OS 의 가독성 요구다.
4. **장식과 조작 기호를 구분한다.** 닫기 ×, 최소화 −, 최대화 □ 는 표준 기호를 쓴다. 상태(오류·진행)는 의미별 토큰과 문구로 전달하며 꽃 모양만으로 표현하지 않는다.
5. **연하고 부드러운 색.** 검은 제목 표시줄은 쓰지 않는다. 연한 면 위에 흰 글자를 기본으로 쓰지 않는다 (accent 버튼만 #28717B 위 #FFFFFF).
6. **정적 장식.** SVG 또는 사전 렌더링 PNG. 실시간 블러·셰이더·상시 회전 효과 없음 (ARM64 소프트웨어 렌더링 포함).

### 3.2 참고 사례

- **뮷즈(국립박물관문화재단)**: "문화유산의 가치와 조형미에 현대의 쓰임을 더한다"는 접근을 참고한다. **참고 사례일 뿐 디자인 범위를 제한하지 않으며**, 브랜드·로고·상품 디자인은 복제하지 않는다.
- **NeXTSTEP**: 명확한 창 구조, 조작 가능성이 드러나는 표현, 도구적 질서. 외형이 아니라 "구조가 읽힌다"는 성질을 가져온다.

### 3.3 폐기된 항목

2000~2005년 레트로 콘셉트, 네이비·실버·앰버 배색, 특정 입체 효과, 픽셀 아이콘, 그리고 "장식은 정보가 아니면 넣지 않는다"는 미니멀리즘 제한은
모두 **폐기**되었다. `docs/DESIGN_LANGUAGE.md`(Graphite)는 이력으로만 남는다. 현재 토큰(`design/tokens/hagra.tokens.json`, status `design-v1`)이 동작 기준이다.

## 4. 평가 기준 (부품·화면 공통)

| 축 | 질문 | 측정 |
|---|---|---|
| 아름다움 | 비례·여백·색의 관계가 일관되고 의도가 읽히는가 | 디자인 검토 (기준 이미지 대비) |
| 접근성 | 텍스트 대비 4.5:1 이상, 포커스가 항상 보이는가, 색 이외 단서가 있는가 | 갤러리 캡처 + 대비 계산 |
| 성능 | 소프트웨어 렌더링(QEMU, 모바일)에서 반응이 유지되는가 | ARM64 TCG 부팅 테스트의 CPU/메모리 수치 |
| 명확성 | 선택·포커스·비활성·오류가 구분되는가 | 갤러리의 상태 행렬 |
| 언어 | 한글·영문·숫자 혼합, 긴 문자열, 조합 중 표시가 깨지지 않는가 | 갤러리 text/inputs 섹션, 대표 장면 파일명 |
| 배율 | 100/150/200% 에서 배치와 선 굵기가 유지되는가 | 갤러리 3배율 캡처, 장면 100/200% |

## 5. 이름과 식별자

- 사용자에게 보이는 이름: **하그라**. 영문이 필요한 곳(GRUB 메뉴, 로그, 영문 문서): HAGRA(임시).
- 내부 식별자(`hagra-shell`, `hagra-session`, `/etc/hagra`, `HagraUI`, `hagralayershell`)는 의존 관계(패키지명, 서비스, 경로, 테스트)가
  얽혀 있어 유지한다. 변경은 컴포넌트 단위로 의존을 확인한 뒤 진행하며, 일괄 치환은 하지 않는다.
  (근거: `tests/`, `image/config/hooks/`, `session/` 이 경로와 바이너리 이름을 직접 참조한다.)
