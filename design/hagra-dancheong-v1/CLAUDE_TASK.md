# Claude Code 실행 지시서 — 하그라 연한 단청 UI

너는 하그라 OS의 구현 담당자다. 이 폴더의 기준 이미지·토큰·자산·명세를 기존 저장소에 통합하여 실제로 실행 가능한 UI를 만들어라. 계획만 제시하고 종료하지 말고 가능한 구현과 검증까지 수행하라.

## 최신 결정이 이전 프롬프트를 대체한다

운영체제 이름은 하그라다. 한국 전통 문양을 현대적인 운영체제의 실제 인터페이스로 재구성한다. 미니멀리즘 제한은 폐기되었다. 뮷즈는 참고 사례이며 디자인 범위를 제한하지 않는다. 색동 띠에만 의존하지 말고 단청의 겹테두리, 연꽃, 구름, 창살, 보자기, 매듭을 적극 사용한다. 연하고 부드러운 색을 유지하고 검은 제목 표시줄은 사용하지 않는다.

한국어 입력·가독성·검색·드라이버·업데이트 품질도 국산 OS 정체성의 일부다. Linux 기반과 자체 개발 범위를 정확히 설명한다. 기존 국산 OS의 실패·한계·성과는 출처를 확인하고 구분하며 전부 실패로 단정하지 않는다. 이번 UI 적용 단계에서 근거 없는 역사 서술을 추가하지 마라.

## 구현 순서

1. 새 작업 브랜치에서 디자인 패키지를 `design/hagra-dancheong-v1/` 등에 넣고 자산 경로를 정한다. 실행용 자산은 QML 모듈과 리소스 구성에 맞춰 편입하고, 기존 MinUI API를 유지한다. 내부 패키지·D-Bus·세션명을 일괄 변경하지 않는다.
2. tokens.json을 기준으로 Theme.qml을 적용하고, 셸의 하드코딩된 Graphite 색상과 고정 크기를 조사하여 토큰으로 연결한다. 현재 28px 패널을 52 논리 px로 바꿀 경우 자식 Layout, 팝업 위치, exclusive zone, 최대화 영역을 함께 수정한다.
3. MinUI 버튼·입력칸·목록 행·메뉴·포커스·비활성·오류 상태를 밝은 테마로 일관되게 구현한다. 기본 TextField와 Button을 나열한 것만으로 완료라 하지 마라. 키보드와 접근성 이벤트가 기존보다 퇴행하지 않아야 한다.
4. 반복 문양 띠와 모서리를 재사용 부품으로 통합한다. SVG는 원본을 보존하고 실제 설치 경로 또는 qrc 경로에서 로드되는지 검증한다. 단순 토큰 변경만으로 문양 UI를 구현했다고 보고하지 마라.
5. labwc 장식에는 우선 밝은 제목 표시줄과 경계를 적용한다. 그림처럼 화려한 전역 제목 표시줄이 현재 버전에서 불가능하면 지원 범위와 차이를 명시하고, 앱 내부 장식 띠로 시각적 목표를 구현한다. 비표준 테마 키를 만들어 넣지 마라. 이 패키지의 OrnamentFrame은 앱 내부 오버레이지 전역 SSD 구현이 아니다.
6. 하단 셸 패널에 장식 띠, 현재 실행 창, 실행 메뉴, 시계·전원 동작을 연결한다. 표시 이름은 하그라로 변경한다. 기존 기능을 장식 이미지로 덮어 가리지 마라. 좌측 도구막대는 실제 실행·키보드 탐색·화면 예약 영역을 구현할 수 있을 때 추가한다. 그렇지 않으면 별도 디자인 미리보기로만 남겨라.
7. files/의 현재 상태를 확인한다. M3가 아직 미구현이면 디자인 검증용 파일 탐색 화면을 독립 예제로 만들고 가상 데이터임을 개발 문서에 명시한다. 실제 복사·삭제·마운트 작업은 이번 범위에서 무리하게 새로 만들지 않는다. 클릭 가능한 것처럼 보이는 미동작 버튼은 데모임을 밝히거나 비활성 처리한다.
8. 배경은 assets/wallpaper.png 또는 같은 원본의 사전 렌더링을 사용한다. 기존 ARM64 소프트웨어 렌더링에서 매 프레임 문양을 다시 그리지 않는다. 지원 조건이 확인되지 않은 실시간 블러·셰이더는 추가하지 않는다.
9. 각 변경을 기존 검사로 확인하고 실제 QML/Wayland 화면을 캡처한다. 기준 이미지와 비교하여 제목 표시줄, 문양 밀도, 폰트, 아이콘, 창틀의 차이를 수정한다.

## 자산·배치 해석

기준 PNG는 시각 방향의 기준이다. 앱 콘텐츠를 PNG로 붙여 넣거나 스크린샷을 버튼 배경으로 잘라 쓰지 마라. 제공 SVG는 재사용 가능한 초안이므로 필요하면 원본을 수정하여 시안에 더 가깝게 다듬어라. 파일마다 다른 상징을 강제하여 분류를 혼란스럽게 하지 마라. 유형과 선택 상태를 작은 크기에서도 구분할 수 있어야 한다.

그림의 닫기 버튼에 꽃 모양이 있어도 실제 제품에서는 명확한 ×를 사용한다. 장식과 조작 기호를 구분한다. 날짜·파일 수·경로·파일명은 런타임 데이터 또는 명시적인 예제 데이터에서 가져오며 현재 날짜를 하드코딩하지 않는다.

## 완료 조건

- 기존 make shell 및 make test-shell을 실행하고 결과를 기록한다. 불가하면 환경 제약과 재실행 명령을 기록한다.
- 관련 부품의 포인터·Tab·Enter·Space 동작, disabled, focus, error를 확인한다.
- 1280×720과 1920×1080 기준으로 배치가 유지된다. 150%, 200%는 논리 작업 영역 축소를 고려해 확인한다.
- 한글 조합 중 텍스트와 긴 경로, 영문 혼합 파일명이 잘리지 않는다.
- 아이콘·문양에 누락된 이미지 표시가 없다. Qt SVG 런타임 의존성을 대상 이미지 안에서 확인한다.
- active/inactive 창은 색 외에도 제목 강조·경계 등으로 구분된다.
- 전역 창 장식과 앱 내부 장식의 구현 범위가 문서에 정확히 나뉘어 있다.
- boot/image/session을 변경했다면 해당 QEMU 회귀 검증을 수행한다. Android 실기기 검증은 실제 수행한 경우에만 완료로 표시한다.
- 장식 포함 실제 구현 스크린샷, 갤러리 스크린샷, 기준 대비 차이 목록을 제공한다.

변경 파일과 검증 결과, 미완성 사항을 요약하라. 저장소의 기존 개발 문서를 최신 철학으로 정리하되 과거 검증 이력은 보존하라. 원격 푸시·병합·배포는 사용자 요청 또는 기존 명시적 승인이 있을 때 수행한다.
